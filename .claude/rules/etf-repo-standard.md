# ETF repos: one standard layout, no per-repo drift

All 29 repos in this folder (AAM aberdeen Amplify ARK Capital-Group Fidelity First-Trust Franklin Global-X Goldman-Sachs Invesco iShares JPMorgan Neos Northern-Trust Pacer Parametric ProShares Schwab SP-Funds SPDR Sprott Tema Themes VanEck Vanguard VictoryShares WisdomTree Xtrackers) are equal siblings. Brand-specific differences are allowed only when the provider truly cannot support something. Owner's words: "all repos must be the same".

## Files
- `scripts/` holds exactly three files: `update-data.config.json`, `update-data.test.ts`, `update-data.ts`. One test file, small inline samples, no fixtures, no UI/app tests, no helper scripts. Big static tables (> ~300 lines) or state the updater writes go to top-level `data/`
- Never keep `.worklog.txt`, `.prompt.txt`, `evidence/`, `research/`, `.plans/`, `COMPLETION.md` or similar artifacts
- `.github/` holds only `workflows/update-data.yml` and `dependabot.yml` (identical in every repo: bun + github-actions, `/`, monthly, limit 10). No pages/ci/checks/probe workflows
- GitHub Pages is deployed by the standard "deploy from branch main /" setting (`build_type: legacy`), never by an Actions workflow
- `update-data.ts` starts with `#!/usr/bin/env bun`, then `/// <reference types="bun" />` (iShares uses `node`), and has git mode 100755 so `./scripts/update-data.ts` works. Never add tsconfig.json or typescript (see bun-only-tooling.md)

## README
Same section order everywhere: title/overview, `## Using Bun`, `## Updating the static <X> data` (with `### Data sources`, `### Metrics and caveats`, `### Update controls`, `### Examples`), `## TypeScript and verification`, `## Brands table`, `## Sibling applications`, `## License` (MIT plus provider trademark/independence disclaimer). The two brand tables are one canonical block generated from `registry.json` (all brands, alphabetical, case-insensitive) and applied with `apply-shared-blocks.ts`; never hand-edit them. Verification section lists exactly: `bun install --frozen-lockfile`, `bun test`, `bun build --target=bun scripts/update-data.ts --outfile=/dev/null`, `git diff --check`

## Tooling (persisted, not in a git repo)
`/Users/maksim.kostromin/Documents/code/private/ETFs/.claude/tools/`: `etf-std/` (registry.json, shared-blocks.md, apply-shared-blocks.ts, check-readme.ts, check-workflow.ts, check-scripts.ts, gen-workflow.ts, about.ts, verify-about.ts, STANDARD.md), `regen-blocks.ts`, plus `verify_merge.sh`, `dep_merge.sh`, `final_check.sh`, `prep.sh`, `blocks_sync.sh`, `pkg_normalize.sh`, `merge_ready.sh`, `dependabot.ref`, `tc/check.sh` (the sanctioned IntelliJ-like type check) and the push-retry rollout scripts. To add or change a brand: edit `registry.json`, run `regen-blocks.ts`, re-apply the block in every repo, and fix tests that hard-code the brand count (they broke when 27 became 29)
