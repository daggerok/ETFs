# ETF updater contract (`scripts/update-data.ts`)

## Controls and precedence
- Defaults live in `scripts/update-data.config.json` (every value a string, keys == `CONTROL_NAMES`). Locally override with environment variables, in CI with GitHub Actions inputs
- Order, identical everywhere (`resolveControls(file, advanced, inputs, env)`): file < `advanced` JSON < nonblank named inputs < env (an explicitly set env var wins even when empty) < protected repo variables (workflow only, e.g. `SEC_UA`)
- Validation is strict: invalid integer/boolean/range/min:max is an error, never a silent fallback. `MAX_RETRIES` is an integer >= 1 everywhere. Reject CR/LF/NUL; never `eval` input
- The CLI and the workflow use the same resolver. Keep brand env aliases (`<BRAND>_<NAME>`, `HISTORICAL_PAGE_SIZE`) working
- Same control surface in every repo where the provider has the data (filters AUM/TER/DIVIDEND_YIELD/SEC_YIELD/PERFORMANCE_*/TOTAL_RETURN_*, MAX_FETCHES, HISTORY_RANGE, page sizes, SKIP_YAHOO, EDGAR_FALLBACK, VERBOSE, SEC_UA). Never keep a no-op control; implement it functionally or omit it and say why in the README. `HISTORY_RANGE` must really shrink the Yahoo request (explicit period1/period2: Yahoo ignores `range` when `period1=0`)
- `USE_SYSTEM_CA` = `auto` (default) | `true` | `false`: the script itself restarts once with `--use-system-ca` on an untrusted-certificate error. Configure only the script, never Bun/BUN_OPTIONS
- SEC contact everywhere: `daggerok ETF feed daggerok@gmail.com` (config default and code fallback, redacted in logs, `SEC_UA` repo variable still wins). Never an example.com address

## Filtered runs never shrink the feed
- A run with `TICKERS`/`MAX_FETCHES`/filters must keep the catalog rows and files of unselected funds: `index.json` always lists every fund that has `funds/*/meta.json`. Incident: a one-ticker workflow run shrank index.json to 1 row in Schwab and WisdomTree (before: Pacer, Goldman-Sachs). Test it with a mocked fetch (one ticker -> same row count)

## index.json metrics contract (hub reads it)
- Every `funds[].metrics` has the same keys, percent numbers, `null` for unavailable (never 0), plus mandatory `returnsBasis` (non-empty text: official NAV vs derived from Yahoo) and `performanceAsOf` (ISO date the returns are as of, not the NAV date, or null). Full table in STANDARD.md section 9a

## Concurrency must be real
- `CONCURRENCY=15 ./scripts/update-data.ts` must fetch funds in parallel: a worker pool with per-worker request lanes that pace `REQUEST_SLEEP` per worker. A single global gate makes CONCURRENCY useless (found in Sprott, aberdeen, Amplify, Franklin)
- Only r.jina.ai proxy traffic keeps one global gate (>= 3.2 s between starts, proxy retried at most once) because the proxy is rate-limited. Prove it with an offline in-flight-counter test (peak 1 at c=1, peak N at c=N)

## Robust writes and honest data (every repo where the provider has the data)
- Every fetch has a timeout (`AbortSignal.timeout`, default 45 s, headers AND body), retried per `MAX_RETRIES`; keep provider-specific 403 handling
- Writes are atomic (tmp file + rename) and ordered per fund: pages first, then `meta.json`, then the index row; stale pages are removed only after the new meta is written. The index is written at the end and the run stops taking new funds at a soft deadline of 25 min so it still finishes inside the 30 min workflow timeout
- Fund-level consistency: the workflow commits after a partial run, which is fine ONLY because every fund is either fully updated or fully kept from before. Build a fund completely in memory, write once; if a required source failed, keep that fund's previous complete state (never a new total return next to stale other columns). Retention replaces a value only when the source FAILED or the page is missing, never for an honest null; `performanceAsOf` and `returnsBasis` travel with the returns they describe
- Write only on real change: a rerun with identical upstream data gives ZERO git diff. `generatedAt` and similar stamps move only when content moved (compare content without stamps). Test: two runs on the same mocked fetch, the second writes nothing
- Fallbacks (EDGAR/N-PORT) never replace fresher data and must verify the fund identity
- New funds: when the catalog has tickers absent from the previous index, print `NEW FUNDS: A, B` and append it to `$GITHUB_STEP_SUMMARY` when set
- `dataFile`: a row without `funds/<T>/meta.json` has `dataFile: null` and still a full `metrics` object (all keys null plus `returnsBasis`); the hub shows only the Overview tab for it
- TER: `terValue` is the NET expense ratio (after waivers; the single number when only one exists), `terGrossValue` the GROSS when published, never invented or a placeholder; the hub shows net with gross in the tooltip and both in the CSV

## Workflow
- `update-data.yml` is generated by `gen-workflow.ts` (spec: name, slug, commitTitle, inputs, protectedVars, requiredControls, extraAdd), never hand-edited. GitHub allows 25 `workflow_dispatch` inputs: 24 individual + `advanced`. Template: weekly cron, `contents: write`, serialized concurrency, `timeout-minutes: 30`, checkout `persist-credentials: false`, `bun install --frozen-lockfile`, `bun test` before the update, runtime-only token push, commit only `api/<feed>` (plus declared extraAdd)
- Output dir stays fixed (`api/<feed>`), never an input
- Providers that block datacenter IPs (e.g. Themes returned HTTP 403 only on GitHub runners) need an r.jina.ai fallback and retained published data; a green local run proves nothing about CI, dispatch the workflow with one small `tickers` input to check
